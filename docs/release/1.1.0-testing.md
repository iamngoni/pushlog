# Pushlog 1.1.0 testing release

Local Flutter / Android build: 26

Latest valid Xcode Cloud build at review time: 48

## What testers should see

### New in build 26 — session details, friend history, and diagnostics

- History days open into full session details, including time, source,
  duration, average rep pace, effort, manual adjustments, and available live
  heart-rate and active-calorie summaries.
- Accepted friends can open each other's profile and see the same shared
  workout-session detail. Private account fields and preferences remain hidden,
  and reporting or blocking immediately removes access.
- Duplicate lead-change notification delivery is suppressed across racing
  snapshot updates and background retries.
- Production Flutter and Worker errors are reported to separate Sentry projects
  with default personally identifiable information disabled.

### New in build 25 — watch workouts and health records

- Starting an iPhone + Apple Watch session launches the watch workout, gives
  the watch ownership of the HealthKit workout, and keeps the phone session in
  sync with watch controls.
- Apple Watch and Wear OS live sessions show heart rate and active calories,
  and allow the tester to record session effort before finishing.
- Completed iPhone workouts can be saved to Apple Health. Completed Android
  workouts can be written to Health Connect with exercise, heart-rate, calorie,
  and effort data when the user grants the relevant permission.
- The installed version and build number are visible in Settings.

### New in build 15 — design system pass

- A rebuilt Today screen. The count sits on a neutral surface with a lime
  progress track while the target is outstanding, and the whole block turns
  Signal Lime once the target is met, so the accent marks something earned
  rather than decorating the screen.
- Logged sets now confirm through a top-anchored toast carrying Undo, instead
  of a bar that stayed pinned above the action strip for the rest of the day.
  Toasts replace every system snackbar in the app.
- Three logging cells instead of four. The old "Live" cell duplicated the
  counted-session button directly above it; the remaining cells are larger
  and easier to hit mid-set.
- Training numbers are set with tabular figures, so counters no longer shift
  the text beside them as they tick over.
- Instructions, errors, and settings copy are sentence case. Uppercase is
  now limited to short labels.
- Empty History and Friends states explain what the feature does and offer
  the action that fills it, and the zeroed summary row is hidden until there
  is something to summarise.
- Consistent icon family, press feedback and haptics on every control, and
  reduced-motion support routed through a single helper.

### Established in build 13

- A one-question-at-a-time onboarding flow for goal, experience, current
  baseline, desired outcome, schedule, consistency preference, coaching tone,
  and reminders.
- Beginner, regular, and experienced starting points with editable targets.
- A 12-week default plan with conservative working sets, selected recovery
  days, and a reassessment marker every four weeks.
- A redesigned Today screen with a clear daily target, counted-session action,
  weekly progress, and a live friend-race summary.
- A dedicated Friends tab with Today, This Week, and All Time rankings.
- An opt-in competitive alert during onboarding. When one friend takes the
  daily lead, both people receive a lead-change notification.
- Accepted friends no longer remain visible as pending or sent requests.
- Plan-aware reminders that are scheduled only on selected training days.
- An editable Training Plan section in Settings.

## Product boundary

The target is an aspiration, not a medical or performance guarantee. The
current algorithm advances estimated capacity gradually and keeps working sets
below that estimate. It does not diagnose injuries or prescribe through pain.

## Internal test pass

1. Complete onboarding once as a beginner and once as an experienced user.
2. Force-close and reopen the app. Confirm that onboarding stays complete.
3. Log the planned set manually, then finish a live session.
4. Confirm that Today progresses toward the target without punishing a planned
   recovery day.
5. Edit the plan from Settings and confirm that the original start date is
   preserved.
6. Enable reminders and confirm that only selected training days are queued.
7. Verify Google and Apple sign-in, cloud restore, HealthKit export, and Watch
   handoff on real devices.
8. Exercise account deletion and local-data reset with test accounts only.
9. Add two test accounts as friends and verify all three leaderboard periods.
10. Overtake the other account's daily score and verify that both devices get
    the correct lead-change notification.
11. Accept crossed requests between two accounts and confirm each person
    appears only once as an accepted friend.

## Store delivery

- Android is delivered from the signed app bundle through the Google Play
  internal testing track.
- iOS is built and distributed by the `Default` Xcode Cloud workflow.
  The workflow archives the shared `production` scheme on `master`, uses the
  latest stable Xcode image, and distributes successful archives to the
  `Internal Testers` TestFlight group.
- Xcode Cloud runs `ios/ci_scripts/ci_post_clone.sh` after checkout to install
  Flutter 3.44.8, fetch iOS artifacts, resolve Dart packages, and install pods.
- Flutter Swift Package Manager integration is disabled for this release. The
  Xcode 27 Cloud onboarding assistant incorrectly requires authorization for
  public transitive packages such as `openid/AppAuth-iOS`; CocoaPods keeps all
  third-party native dependencies behind the primary PushLog repository.
- The Flutter/Play store build number for this release is 26. Xcode Cloud
  manages its own monotonically increasing build number; build 48 was the
  latest valid archive when this checklist was reviewed.

## Signed artifacts

- Android: `build/app/outputs/bundle/productionRelease/app-production-release.aab`
- iOS: produced and retained by Xcode Cloud after a successful archive action.

The build artifacts are local output and are not deployment proof. Store-track
submission and tester availability must be confirmed separately in Play
Console and App Store Connect.
